# 街角早餐铺

一个关于“被记住的那一口”的中文早餐经营小游戏。你经营一家街角小店，为有不同口味和故事的街坊做早餐。

> **当前状态：Canvas 2D 可运行 Demo 源码，自动规则 / 生命周期测试已通过，真实浏览器、手机与抖音官方运行验证尚未通过。** 独立非公开 GitHub 仓库已建立。所有实际玩法、美术和控件均由 Canvas 绘制；原来的 DOM 界面草稿已归档，不参与正式入口。项目优先跑通 Demo，再走抖音测试 / 体验版验证，未来考虑微信适配。不得把当前源码或适配器宣称为已上架产品。

## 0.3.0 五十班早高峰

当前可玩内容为 **50 班、9 位街坊、三种早餐**。前五班保留最初19单教学及错料后随时重做；6–10班可以切换顾客、熟悉排队，但没有失败压力；后面才逐步加入会因选择失误而失败的挑战。

- **11–20班：先照顾谁。** 最多三位顾客同时等候，头像写明还可等几锅。只有真正开火才推进锅次，阅读订单、换台面、开菜单均不消耗耐心，没有隐藏倒计时。新进入可见队列的单客至少获得1锅机会，同桌至少2锅，不会刚出现就过期。
- **21–30班：余温的取舍。** 同火候连做消耗1格炉火，换火候消耗2格；开火前清楚显示本锅消耗。优先照顾急客还是连锅节省炉火，需要取舍。原料可以撤回，重做本身不扣分，但已经用掉的炉火和锅次不会返还。
- **31–50班：一桌人一起吃。** 同桌订单要两份都做好，第一份放入保温位，再做第二份并一起交付。保温最多等2锅；可以取回、交换或倒掉重做，不能把凉餐或错料强行交给顾客。后期有更紧的炉火与队列约束。
- 排队安排不当、炉火耗尽或熟食放凉会明确提示失败原因。**每关初始都存在不用工具、不看广告的参考解，50个参考计划均经规则、Canvas指针及原样离线HTML回放验证。** 不是投放“初始无解”的收费关。
- 每班胜利首通得12–20金币，重玩通关得2金币；同一局结算只发一次。金币仅用于限定工具和续摊，无现金购买、提现或交易。小炭包/街坊茶各18金币，库存各最多3个，每班各最多用1次；续摊30金币，与广告续摊共用每班一次额度。
- 未完成班次有消费凭证：刷新或主动重开会退回本班所用工具和续摊金币一次，通关则核销、不退款。购买但未用的库存保留；退款时库存已满，溢出工具按18金币原价退回。存储写入失败时，不执行扣款/消耗，也不发付费效果。
- **失败始终可免费重开。** 一次续摊只补4格炉火、2锅耐心，并恢复现有熟食鲜度，不保证之后一定获胜，难度仍需靠调度解决。
- 浏览器/离线版只有明确写着“模拟广告 · 非真实广告”的完成/取消/无填充/异常四结果测试。取消、异常、旧局回调均无奖励。抖音候选真实广告默认关闭，没有广告位ID，也不创建广告实例。
- 旧五关存档自动迁移，保留星级、最佳分与音量，不赠送伪造金币或解锁。仍使用原存储key，由内容版本区分格式。

50班由保留教学和确定性参数化班次组成，逐步组合排队、余温和同桌机制，不是50套完全不同的玩法。美术增加九种角色装束、耐心状态、食材预览、焦纹/融芝士/米粒与蒸汽动画；所有操作仍在安全区内的Canvas上。

详细广告预留边界见 `docs/REWARDED_AD_CONTRACT.md`，50班参考解证据见 `artifacts/reference-plans.json`。模拟SDK、原生Canvas和自动测试不能代替真实浏览器或平台真机验收。

## 历史：0.2.0 手机街摊界面

这版不再把食材、火候、包装排成一张网页表单。玩家站在暖晨街摊后，通过三个台面制作早餐：食材盒里的“备料台”、铁锅与火候牌组成的“铁锅台”、盘子和纸袋组成的“出餐台”。顾客票据一直留在上方，口味要求和错误恢复提醒不随切站消失。

- 所有操作都在 Canvas 内：开场、选关、教学、配方本、声音、重开确认、侧边栏入口、结算和重玩。HTML 仅提供全屏 Canvas 宿主，没有外部卡片、按钮或说明。
- 摊位菜单是一块小黑板，配方 / 关卡 / 结算是摊主手账和票据；声音、菜单等图标手绘，不依赖稀有字体符号。
- 三台面底部一直保留高对比“清空食材 / 倒掉重做 / 收拾台面”，免费恢复，不丢当前顾客或已得分。切换台面继续煎制，打开菜单或说明暂停。
- 以可用安全宽度布局，不再把整个页面缩小塞进短屏。浏览器读取 safe-area CSS 变量；抖音适配器读取安全区和可用胶囊边界，并保留顶部空间。实际宿主边界仍需真机检查。
- 320×568、顶部安全区最高 92px / 底部 34px，以及左右各 12px 的模拟布局都检查过。已测全部操作目标至少 44 实际像素且无相互覆盖，桌面保持竖屏台面。
- 全部三道配方、五天 19 单与 0.1.1 规则保持不变，旧存档格式兼容。

原生 Canvas 像素检查已完成，发现并修复欢迎标题叠店招、桌面提示被底部台沿遮挡、短屏关卡行重叠和短屏结局文字间距。这是 Linux 原生 Canvas 的真实绘制结果，不是真实浏览器或手机截图。

## 0.1.1 用户反馈修复

用户指出多放食材并煎熟后，既不能撤回食材，也不能交给顾客，找不到继续的方法。旧规则中清空其实可用，但恢复仅是很淡的小字；界面仍写“再点一次可以撤回”，煎好时还一律提示可以出餐，造成操作陷阱。

现在三个台面的底部都常驻高对比恢复按钮：备料时“清空食材”，烹饪中 / 熟食时“倒掉重做”，交付后“收拾台面”。清空不扣分、不换订单、不删除已得成绩；已交付订单不重复记分。熟食不能退回原料，配料 / 火候错误会明确引导重新做；仅包装错误直接改袋 / 盘即可。错单校验仍保留。

0.1.1 恢复按钮曾在 320×568 下约 63×45 像素；0.2.0 常驻按钮扩大为 110×62 逻辑像素，320px 无左右内边距时约 98×55 实际像素。五种视口、每道配方的所有单种多余食材、全部七种原料一起放入，以及 19 单逐单故意做错后恢复都通过模拟回归。这里的“通过”指 Node / 模拟 Canvas 和原样离线 HTML 输入，不是已完成真实浏览器视觉或手机测试。

旧 0.1.0 早餐候选已作废，0.1.1 候选由本次界面版取代，记录见 `artifacts/invalidated-candidates.json`。使用 `dist/breakfast-demo.html` / 新离线包和当前 0.3.0 冻结清单，禁止上传或再次分发旧候选。

## 已实现的 Demo 玩法

- 三道配方：招牌煎饼、芝士蛋饼、香煎饭团。
- 50班确定性递进挑战；前5班保留19份原始教学订单。
- “不吃葱 / 赶时间 / 想吃脆的”等对白，对应清晰的葱花、火候和包装要求；不惩罚猜谜。
- 实际点选食材 → 选择火候 → 加热 → 堂食或打包 → 出餐；失误后可清空重做。
- 每单有明确配方小抄，也可打开全部配方。错单不推进；重复交付不能重复计分。
- 固定角色、回头客对白、逐日小故事和雨天街景。所有叙事为本地规则内容，不使用运行时 AI。
- 通关解锁、星级、最佳成绩和音效开关通过平台存储保存；存储失败可继续玩。
- 原创程序绘制插画与本地合成短音效，不买素材、不联网取素材。

## 本地启动

需要 Node.js 20 或更新版本，无第三方运行依赖，不需要 `npm install`。

```sh
npm run serve
```

浏览器打开 `http://localhost:4173`。可通过 `PORT=4174 npm run serve` 改端口。受限云执行环境若每个命令使用独立网络命名空间，服务日志“监听成功”不代表浏览器可达，需使用该环境支持的共享服务方式。

```sh
npm test
npm run check
npm run build:tt
npm run build:offline
npm run validate:shifts
```

当前 183 项 Node 测试全部通过，包括全部50班参考解、完整Canvas与精确离线HTML通关、旧错料恢复、失败/续摊、金币去重、存档迁移、安全区和奖励服务测试。浏览器流程测试脚本为 `scripts/browser-smoke.mjs`，需要能够访问本地服务并启动 Chromium 的环境；没有跑完该脚本不能宣称真实浏览器通过。结果与限制见 `TEST_RESULTS.md`。

`npm run build:tt` 生成 `dist/douyin/`，含入口、配置与短音效，不含 HTML / CSS / 归档内容。默认使用已核实创建的非敏感 AppID `ttebf69d4b758f209102`，项目名为“街角早餐铺”，版本 `0.3.0`。构建产物只是待上传候选，尚未完成官方工具或真机运行验证。当前使用固定文件 Demo 装配脚本，并非通用 ESM 打包器；扩展依赖或模块语法前应换用经过锁版本验证的构建工具。

## 抖音候选配置与冻结

`config/douyin.json` 保存非敏感 AppID、项目名、版本和说明，不包含令牌、联系资料或登录信息。`DOUYIN_APP_ID` 可覆盖构建 AppID；未设置时使用核实配置，空字符串仅供模拟测试，不能上传。测试结束会恢复真实 AppID 候选。

```sh
DOUYIN_APP_ID=ttebf69d4b758f209102 npm run build:tt
```

构建产生 `dist/douyin-build-manifest.json`，记录实际 AppID、版本、每个待上传文件和关键源码的 SHA-256。上传前将最终清单冻结在 `artifacts/douyin-candidate-manifest.json`，同步源码并核验远端提交后再交上传流程。构建脚本不登录、不上传；“上传成功”也不等于真机通过或正式发布。

侧边栏是可选真实入口：同步注册最新 `tt.onShow`，用 `tt.checkScene` 检测能力；支持时显示 Canvas 入口，玩家阅读说明后点明确按钮才调用 `tt.navigateToScene`。失败或取消会恢复，不支持时隐藏入口且照常游玩。只有最新 `onShow` 同时包含 `homepage` 和 `sidebar_card` 才显示“本次从侧边栏回来”；导航 success 不假称回访。没有奖励，也不承诺平台审核通过。

## 工程结构

- `game.js`：配方、顾客、关卡、评分、状态机、安全存档解析。
- `src/main.js`：导出 `startGame(platform)`，Canvas 游戏、输入、制作与结算流程。
- `src/canvas-art.js`：原创程序化街景、人物、食材与料理插画。
- `src/platform-contract.md`：平台抽象契约。
- `adapters/browser.js`：浏览器 DOM / 指针 / 音效 / 存储 / 生命周期隔离层。
- `adapters/tt.js`：抖音运行时适配器候选，尚不代表官方验证完成。
- `adapters/douyin-sidebar.js`：真实能力检测、导航与最新前台来源状态。
- `config/douyin.json`：核实的非敏感应用配置。
- `index.html`：只挂载 Canvas 的浏览器启动页，不含 DOM 玩法控件。
- `assets/*.wav`：原创本地合成短音效。
- `tests/`：Node 内建测试。
- `scripts/browser-smoke.mjs`：真实浏览器流程回归脚本。
- `scripts/build-offline.mjs`：只构建早餐铺的单文件离线 Demo。
- `tests/offline.test.js`：执行重建 HTML 的原样内嵌脚本，检查用户反馈路径和恢复。
- `archive/h5-draft/`：已停止扩展的早期静态 DOM 设计草稿，禁止加入小游戏构建。

## 测试版边界

这是 Canvas 2D Demo，不是已经通过抖音或微信审核的小游戏，也没有公开部署。

没有后端、账号系统、真实广告投放、内购、支付、排行榜、联机或用户行为采集。模拟广告不是商业广告。浏览器记录不是云存档；清除数据、换设备或换平台不能恢复。保存已完成关卡、声音、金币和工具库存；不保存当前未完成的一班。320px 起的竖屏使用安全宽度布局，短屏压缩装饰而不缩小所有控件；尚未为低于 320px、极短横屏和动态大字体做好完整适配。当前主要支持触控和鼠标，Canvas 的键盘及屏幕阅读器支持仍需补齐。

1. 候选入口、配置和模块装配已生成，浏览器启动页与归档草稿已排除；仍需核对真实平台配置和运行行为。
